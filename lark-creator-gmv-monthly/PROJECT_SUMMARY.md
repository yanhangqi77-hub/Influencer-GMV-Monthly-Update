# 项目总结：`lark-creator-gmv-monthly` — 达人 GMV 月度更新

> 交付日期：2026-09-17

## 一、一句话定位

一个面向 TikTok Shop 达人运营的**个人自动化 Skill**：把「原始订单清洗 → 达人 GMV 汇总 → 涨佣候选筛选 → 飞书表格更新」这一整套月度工作流，沉淀为**可重复、可核验、可审计**的标准化工具。

---

## 二、解决的核心问题

达人 GMV 月度核算与佣金调优，原本依赖**人工 + 表格**，存在三个痛点：

| 痛点 | 后果 |
| --- | --- |
| 口径靠人记、容易错 | 订单去重、取消/退款扣减、渠道/SKU 分类每次判断不一 |
| 涨佣判断靠"总单量拍脑袋" | 不看单个产品达标，可能误判、误涨 |
| 手工维护字段易被覆盖 | 佣金、合作类型、备注刷新时可能按行号错位、丢失 |

本 Skill 把这些**隐性规则显式化**，用脚本 + 飞书 API 自动执行，并强制**回读核验**后才算完成。

---

## 三、核心流程（Pipeline）

```
① 指令路由        月度归档  vs  最新滚动表（复用稳定 sheet_id，改名不新建）
        ↓
② 数据清洗        去重 → 排除取消/未付款 → 按 Paid Time 归月 → 剔除敏感履约字段
        ↓
③ GMV 汇总        按达人 × 渠道(Videos/LIVE/Product cards) × SKU(503/303/509) 三维聚合
        ↓
④ 涨佣筛选        按「单产品净件数」选档 → 比对当前佣金 → 输出候选/待核实/保护
        ↓
⑤ 飞书写入        重命名+覆盖写入 + 样式 + 条件格式 + 联动公式，最后回读核验
```

**关键设计**：本地脚本只生成 JSON 写入包，**不直接改飞书**；写入后必须从飞书**回读对账**（行数、GMV、渠道、人工字段），杜绝"本地生成成功 ≠ 线上正确"。

---

## 四、关键业务规则

- **GMV 口径**：取 `Order Amount`；空达人/账号 `62` 归 `Unattributed`（计入总 GMV，不参与排名）。
- **涨佣口径（重点）**：按**单个产品各自的净件数**选档，而非所有产品合计——`303&503` 组合同时计入两者，广告佣金同样按单产品。档位：10件→12%/4%，30→13%/5%，80→14%/6%，100→15%/7%，500→18%/8%。
- **人工字段保护**：合作类型/503/303/509/Ad/持续时间/备注，**按规范化达人账号继承**，绝不按行号。
- **联动**：「佣金情况汇总」用 FILTER+HSTACK 公式，只纳入四项佣金至少一项有数据的达人。

---

## 五、本次迭代的改进（工程亮点）

| # | 改进 | 价值 |
| --- | --- | --- |
| 1 | **涨佣口径**：合计件数 → **单产品件数**选档 | 修复"一个产品达标却给所有产品涨佣"的错误 |
| 2 | **序列化 bug**：空值从 `null` 改为 `""` | 飞书 overwrite 会跳过 null 不清旧值，导致达人排名变动后残留他人佣金 |
| 3 | **样式残留 bug**：数据区整块刷白 | 修复旧「合计行」绿色背景泄漏到普通达人行 |
| 4 | **颜色含义澄清** | 橙色=未寄样但出单的达人（需建联），浅蓝=涨佣候选 |

每一步都配套了**离线单元测试**（30 用例全通过），保证规则变更不回归。

---

## 六、技术实现

- **离线生成**：Python + pandas，清洗/汇总/涨佣筛选 → 产出 `manifest`、表格/样式/条件格式 payload、佣金审计。
- **在线读写**：`lark-cli`（飞书 CLI）驱动，走用户态 OAuth；读写前用 `--dry-run` 预览、高风险操作显式确认。
- **质量保障**：`unittest` 覆盖清洗、净件数扣减、单产品档位、人工字段合并、公式等。

---

## 七、成果与价值（本轮实测）

以 2026-09 最新滚动表为例：

- 清洗 **1,500 单**，总 GMV **¥11,647,827**（Videos 629万 / LIVE 215万 / Product cards 320万）；
- 汇总 **59 个达人** + 494 单未归因；
- 涨佣筛选：**1 个候选**（`yume_bound.code`，503 净 54 件 → 自然 12%→13%、广告 4%→5%）、3 个历史高佣保护、8 个待核实；
- 全流程对账一致、公式零错误、人工字段零丢失。

**核心价值一句话**：把一个"每月要做、容易错、难追溯"的运营动作，变成了**几分钟跑完、每一步可回读验证、规则可版本化**的可靠流程。
